# 小天才反馈收集与发布说明

日期：2026-11-03。适用：企微 / 飞书 bridge；版本分支 `codex/feedback-collection`。

## 用户路径

在已授权群里 @小天才发送 `反馈：页面、操作、预期和实际结果`。bridge 直接持久化，成功后返回反馈编号；不需要调用模型。普通聊天不会自动登记。`/help`、`反馈帮助` 可查看入口。

| 操作 | 发送内容 |
|---|---|
| 新反馈 | `反馈：客户列表点击下一页没有反应`，支持多行原文 |
| 查询 | `反馈列表`、`反馈列表 2`、`查看反馈 编号`、`查看反馈 编号 2` |
| 补充 | `补充反馈 编号 Safari 也能复现` |
| 汇总 | `反馈汇总`：当前会话全部记录的分类/状态/待定负责人数量，以及最早 5 条待跟进反馈 |
| 分类 | 管理员：`反馈分类 编号 Bug`（或 `体验` / `需求` / `待分类`） |
| 负责人 | 管理员：`反馈负责人 编号 张三`（必须先由人确认） |
| 状态 | 管理员：`反馈状态 编号 处理中`；关闭必须写结果：`反馈状态 编号 已解决 修复已验证` |
| 关联重复 | 管理员：`关联反馈 编号 另一编号`；仅本会话，保留每条原始反馈，不重复计为独立问题的已核验数量 |
| 附件 | 私聊新建反馈 → `反馈附件 编号` → 10 分钟内发送图片/文件；每次至多 5 个，每个 20MB |
| 取回附件 | `查看反馈附件 编号 1`；`取消反馈附件` 可取消等待上传 |

状态：待确认、待处理、处理中、已解决、不处理。Bug/体验/需求由管理员确认，不由规则猜测；初始待分类。关闭理由、补充、分类、负责人、关联均保留操作人、消息 ID 和时间。

企微群当前收不到图片/文件：群里的反馈与私聊反馈不会自动关联或公开。需要私聊另建反馈后传附件；管理员可在获得授权后将必要的非敏感结论补充到群反馈。附件仅保存与取回，不自动 OCR、执行或让模型读取。明确提交与附件同一消息且平台已提供资源时，一并保存；文本成功、附件失败会分别说明。

## 身份、权限与存储

- 入口在原有 intake 的群/成员权限与 @ 检查之后、LLM 之前。不会扩大 `access.allowedChats`、`allowedUsers`、`admins` 或 `mode`；原有 team 模式仍遵循原访问策略。
- 从平台消息取得 sender、chat、thread、message ID，不接受正文自报身份。按配置根目录、profile、tenant、Bot ID、会话隔离；话题群按 thread 隔离；私聊额外绑定 sender。
- 已获准成员可提交、查看、补充当前会话反馈；只有现有 owner/admin 可修改状态、分类、负责人和重复关联。其他群/私聊即使知道编号也无法通过反馈命令访问。
- 路径：`<配置根>/profiles/<profile>/feedback/<scope-hash>.json`；附件在该目录的 `attachments/<scope-hash>/`。这是专用反馈数据，不是原业务台账、聊天知识库或已停用 Todo 系统。
- JSON schema v1，首条写入自动创建；进程间锁、临时文件写入与 fsync 后原子替换；文件 0600、目录 0700。相同来源消息重试不重复建单；补充/状态/附件按消息 ID 幂等。损坏文件或写入失败不覆盖旧文件、不宣称成功。
- 反馈命令的隔离不等于宿主机文件系统多租户隔离：运行 bridge 的 OS 账号和具备该目录读取权限的本地进程是受信任管理员。不要给不可信成员宿主机 full access；现有 agent sandbox/执行策略仍需独立配置。system prompt 要求模型不得绕过反馈命令读取其他会话记录，但提示词本身不是 OS 安全边界。
- 原文、附件可能含个人数据，不入 Git，不写入错误日志，不跨群自动推送，不自动生成工单/承诺排期。相似问题仅人工关联，汇总按原始反馈条数统计；没有语义去重或自动优先级评分。
- 一次查列表 10 条，详情按 3000 字符分页，不静默截掉后续补充。附件下载完成后检查体积；WeCom SDK 可能先将附件读入内存，因此 20MB 是接收后校验，不是传输层限流。

## 发布、验证和回滚

本次默认生效，无需手工启用；没有新增功能开关或依赖服务。现有访问白名单、群 @ 策略、显式权限限制仍会限制入口；不会被本次默认值覆盖。`LARK_CHANNEL_HOME` 继续指定配置根目录，显式配置路径优先于默认 `~/.lark-channel`；不更改 Codex 模型或登录配置。

1. 核对目标机器、当前运行 profile、Git SHA 与配置根；备份完整 profile 的 `feedback/`（首次部署无该目录）。不要从临时 worktree 直接注册常驻服务。
2. 将通过审查的提交同步到目标长期部署目录，执行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm build`。沿用现有 Node/pnpm/企微 SDK，无新依赖。
3. 只重启目标 profile：先 `node bin/lark-channel-bridge.mjs stop --profile wecom-codex`，再 `start --profile wecom-codex`。若迁 Mac mini，先停旧机，再启动 mini，避免同 Bot ID 两个连接。
4. 原生反馈路径不依赖模型；新 prompt 对已有模型会话的生效仍以 adapter 行为为准，需要时用户主动 `/new`。不要自动清除会话历史。
5. 用真实授权成员群 @ 提交 → 查询 → 补充 → 汇总；检查另一群按同编号无法查询，普通成员不能修改状态，管理员关闭需理由。未经授权者应在原 intake 被拦截。
6. 私聊选择反馈后传测试附件、取回；重启后查回反馈和附件。测试空列表、只读目录写失败、群附件提示。真实平台测试会发送回复，须获得目标群/账号授权后执行。
7. 回滚：停止此 profile，恢复旧代码/构建，再启动。保留反馈目录，旧代码忽略它；不要删除反馈或附件。后续升级必须保持 schema v1 读取兼容。

反馈 JSON 采用每会话读写，适合团队反馈台账；记录持续增加时应观察文件体积与处理延迟，再做有备份与迁移验证的存储升级。停服后整体备份反馈目录可保证记录/附件一致；活跃复制不保证事务一致。下载中断的临时文件尽力清理，进程异常或部分附件失败可能留下未关联 blob，维护时需停服核对再清理。

## 验证记录

本次新增 10 项离线测试覆盖真实命令入口、保存/重启、并发幂等、权限、跨会话、关闭理由、损坏/不可写文件、附件保存与取回、附件失败/取消、多页详情。验收不调用真实模型或企微。

Mac mini 部署、真实群 @、实际附件回传、既有本机 agent 权限审计仍需在目标机验证；代码检查通过不代表这些项目通过。
